## 3. 기능 요구사항 (Functional Requirements)

### 3.1 고객용 기능 (Customer)

**FR-C1. 테이블 태블릿 자동 로그인 및 세션 관리**
- 관리자가 1회 초기 설정: 매장 식별자, 테이블 번호, 테이블 비밀번호 입력 → 로그인 정보 로컬 저장
- 이후 저장된 정보로 자동 로그인

**FR-C2. 메뉴 조회 및 탐색**
- 메뉴 화면이 기본 화면으로 항상 표시
- 카테고리별 분류/표시, 카테고리 간 빠른 이동
- 메뉴 상세: 메뉴명, 가격, 설명, 이미지(외부 URL)
- UI: 카드 레이아웃, 터치 친화적 버튼(최소 44x44px), 명확한 시각적 계층

**FR-C3. 장바구니 관리**
- 메뉴 추가/삭제, 수량 증감, 총액 실시간 계산, 장바구니 비우기
- 클라이언트 측 로컬 저장 (새로고침 시 유지), 서버 전송은 주문 확정 시에만

**FR-C4. 주문 생성**
- 주문 내역 최종 확인 → 주문 확정
- 성공 플로우: 주문 번호 표시 → 장바구니 자동 비우기 → 메뉴 화면으로 자동 리다이렉트
- 실패 시: 에러 메시지 표시, 장바구니 유지
- 주문 정보: 매장 식별, 테이블 식별, 메뉴 목록(메뉴명·수량·단가), 총액, 세션 ID

**FR-C5. 주문 내역 조회**
- 주문 시간순 정렬, 주문별 상세(주문번호, 시각, 메뉴·수량, 금액, 상태[대기중/준비중/완료])
- **현재 테이블 세션 주문만** 표시 (이전 세션/이용 완료 주문 제외)
- 페이지네이션 또는 무한 스크롤

### 3.2 관리자용 기능 (Admin)

**FR-A1. 매장 인증**
- 매장 식별자 + 사용자명/비밀번호 로그인
- JWT 기반, 16시간 세션 유지, 새로고침 시 세션 유지, 16시간 후 자동 로그아웃
- 비밀번호 bcrypt 해싱, 로그인 시도 제한

**FR-A2. 실시간 주문 모니터링**
- **SSE 기반** 주문 목록 실시간 업데이트 (2초 이내 표시)
- 그리드/대시보드 레이아웃: 테이블별 카드, 카드에 총 주문액·최신 주문 n개 미리보기
- 주문 상세: 테이블 번호, 주문번호, 시각, 메뉴·수량(축약), 총액
- 주문 카드 클릭 시 전체 메뉴 상세 보기
- 주문 상태 변경(대기중/준비중/완료), 신규 주문 시각적 강조, 테이블별 필터링

**FR-A3. 테이블 관리**
- 테이블 태블릿 초기 설정(테이블 번호/비밀번호, 16시간 세션 생성, 자동 로그인 활성화)
- 주문 삭제(직권 수정): 확인 팝업 → 즉시 삭제 → 총액 재계산 → 피드백
- 테이블 세션 라이프사이클: 세션 시작(첫 주문)~종료(이용 완료) 관리
  - 종료 시 해당 세션 주문을 과거 이력으로 이동, 현재 주문 목록·총액 0으로 리셋
  - 새 고객이 이전 내역 없이 시작 가능
- 과거 주문 내역 조회: 테이블별 시간 역순, 주문번호·시각·메뉴·총액·이용완료 시각, 날짜 필터

**FR-A4. 메뉴 관리**
- 메뉴 조회(카테고리별), 등록(메뉴명·가격·설명·카테고리·이미지 URL), 수정, 삭제, 노출 순서 조정
- 데이터 검증: 필수 필드, 가격 범위

### 3.3 데이터 / 시드
- 엔터티(초안): Store, Table, TableSession, Menu(Category 포함), Order, OrderItem, OrderHistory, AdminUser
- 주문 이력은 세션 ID로 그룹화, 완료 시각 기록
- 시드 데이터: 샘플 매장 1개, 테이블 수 개, 카테고리별 메뉴, 관리자 계정 1개 → 즉시 시연 가능

## 4. 비기능 요구사항 (Non-Functional Requirements)

| 구분 | 요구사항 |
|------|----------|
| **성능** | 신규 주문이 관리자 화면에 **2초 이내** 반영(SSE). 소규모(단일 매장, 테이블 수십) 기준 |
| **실시간성** | SSE 단방향 푸시(서버→관리자). 연결 끊김 시 자동 재연결 고려 |
| **보안(기본)** | 관리자 비밀번호 bcrypt 해싱, JWT 세션(16h), 로그인 시도 제한. (별도 Security 확장 규칙은 **미적용** — 아래 5절) |
| **사용성** | 터치 친화적 UI(버튼 ≥44x44px), 카드 레이아웃, 명확한 시각적 계층, 신규 주문 강조 |
| **데이터 지속성** | SQLite 파일 DB. 장바구니는 클라이언트 로컬 저장 |
| **이식성/실행** | 로컬 단일 머신 실행. 별도 클라우드/컨테이너 인프라 불요 |
| **유지보수성** | 프론트/백엔드 분리, API 계약 명확화(4인 병렬 개발 지원) |

## 6. 범위 외 (Out of Scope — constraints.md)

- **결제**: 실제 결제(카드/현금/디지털), PG 연동, 영수증, 환불, 포인트/쿠폰
- **인증/보안(고급)**: OAuth/SNS 로그인, 2FA/OTP
- **파일/콘텐츠**: 이미지 리사이징/최적화, CMS, 광고
- **알림**: 푸시/SMS/이메일/소리·진동 알림
- **주방**: 주문 주방 전달, 식재료 재고
- **고급 기능**: 데이터 분석/대시보드, 매출 리포트, 재고 관리, 직원/권한 관리, 예약, 리뷰, 다국어
- **외부 연동**: 배달 플랫폼, POS, 소셜 공유, 지도 API, 번역 API

## 7. 핵심 요구사항 요약

- 브라우저 기반 **고객 주문 앱 + 관리자 운영 앱**을 단일 백엔드로 구동하는 MVP
- 핵심 흐름: (고객) 자동 로그인 → 메뉴 조회 → 장바구니 → 주문 → 현재 세션 내역 조회 / (관리자) 로그인 → 실시간 모니터링(SSE) → 주문·세션·메뉴 관리
- 스택: **React SPA + Node.js + SQLite + SSE**, 로컬 실행, 시드 데이터로 즉시 시연
- **테이블 세션 라이프사이클**(시작~이용 완료→이력 이동)이 도메인 핵심 규칙
- 결제·알림·외부 연동 등은 범위 외
