# P3 코드 생성 요약

상태: **기본 고객 앱 구현 / 전체 인수 미완료** · 2026-09-07

## 범위

`client-customer/`에 로그인, 메뉴, 장바구니, 주문 확인/성공, 현재 주문 내역 화면과 공통 API·저장·포맷·인증 상태를 구현했다. P1/P2 서버 소스, DB 스키마, P4 앱은 수정하지 않았다.

API 어댑터는 기존 계약의 로그인, 메뉴, 주문 POST, `/orders/mine`만 소비한다. 승인된 설계의 품절 카드 표시, 5초 성공 화면, 10건 페이지네이션을 적용했다. 주문 시 최신 메뉴 검증, 가격 변경 재확인, 201 성공 시 초기화, 응답 불명 상태의 영속화 및 수동 접수 확인 절차를 구현했다.

테스트는 storage/format/cart 순수 로직과 app.test.jsx의 인증·메뉴·주문·내역 시나리오로 구성한다. 반복되는 앱 픽스처를 줄이기 위해 계획의 개별 컴포넌트 테스트 파일을 app.test.jsx로 통합했다.

## 검증

- npm ci: 통과 (Node 24.15.0 / npm 11.16.0).
- npm test: 4개 파일, 25개 테스트 통과.
- npm run build: 통과, JS 약 258 kB / gzip 약 82 kB.
- Playwright: 5개 시나리오 작성. 기존 서버를 인메모리 DB로 부팅하는 픽스처 포함. Chromium의 libnspr4.so 누락 때문에 브라우저 시작 전에 실패. 기능 테스트 통과로 계산하지 않는다.
- 앱 소스/테스트 내 관리자 호출은 e2e 테스트 픽스처에만 존재한다.

## 열린 항목

1. Step 8: P1의 현재 착석 세션 식별 계약 미확정. 이용 완료 후 로컬 카트 자동 초기화 미구현.
2. Step 9: 지원 브라우저 환경에서 E2E 5개 시나리오 및 화면 실측/시각 검토 필요.
3. P4 관리자 브라우저를 포함한 전체 E2E는 범위 밖이며 미실행.

사용자가 P3 범위를 재확인하고 커밋/푸시를 요청했다. 미완료 항목을 숨기거나 전체 유닛을 완료 처리하지 않고 현재 P3 변경을 작업 브랜치에 게시한다.
